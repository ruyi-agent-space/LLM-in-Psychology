# Public metadata automation

Run `python -m unittest discover -s tests -p 'test_*.py' -v`, then `python scripts/refresh.py` with Python 3.10+. No third-party Python dependencies or API credentials are needed. The script reads and validates the separately curated `data/research.json` and `data/graph.json`, but never edits them. Only `data/radar.json` and `site/radar-data.js` are generated. Use `--root PATH` for another checkout and `--force-weekly` to manually rebuild the weekly sample.

The GitHub Actions workflow runs daily at 06:00 UTC on main (actual execution may be delayed by GitHub). Weekly summaries update on Monday UTC, or on first successful initialization. If Monday fails, the next successful run catches up once for the current UTC week. Manual workflow runs refresh the daily list and catch up an overdue weekly sample. Changes to the refresh script or workflow also trigger verification runs. Actions must be enabled and the repository must permit the built-in token to push to main; protected-branch requirements can block commits. There is no Pages deployment, external publishing, private-data access, or extra secret. The only requested token permission is `contents: write`. The workflow runs tests, records refresh status, commits both generated files even when metadata providers fail, uploads the standalone site as a downloadable artifact, then marks the run unsuccessful for any warning/error. GitHub may disable scheduled workflows in inactive public repositories.

## Sources, dates and selection

Europe PMC's public REST search returns up to 300 core metadata records across three cursor pages, constrained to first publication within 90 days. arXiv's public Atom API returns up to 200 newest submitted matches. Both broad queries require LLM terms plus psychology-related topics. Abstract text is used only in memory for matching; output contains title, URL, dates and descriptive metadata, not full texts. Failed requests receive two bounded retries, then a visible source error.

Local positive relevance matching requires an LLM term and one of the five psychology topic vocabularies. Methods matches additionally require psychological/human research context. This is a transparent heuristic, not full-text screening. It can miss papers, misclassify ambiguous matches, and reflects source coverage and query caps. Europe PMC records are labeled `paper` (not a peer-review guarantee) unless explicitly preprints; arXiv entries are `preprint` even if a later journal version exists. This implementation retrieves papers/preprints, not social-media posts. No attempt is made to infer clinical efficacy or research quality.

Only known original `publishedAt` dates within the previous 90 days qualify. Future/missing publication dates are excluded; missing, inconsistent or future `updatedAt` becomes null. Europe PMC does not supply a trusted revision date here, so `updatedAt` remains null. A newly revised older arXiv paper is not treated as newly published. Duplicate groups use DOI, normalized title or source ID, including transitive matches; published-source records take precedence over preprints. DOI-less differently titled versions may remain undetected.

Daily selection score: `90 - age_in_days + 3 * min(title_topic_hits, 3)`, descending, with source ID as deterministic tie breaker. Select one per direction first, then fill to three only when fewer directions are available. Thus multiple clinical papers do not crowd out eligible alternatives. The score measures metadata relevance and freshness, never scientific quality.

Weekly output has exactly five fixed bilingual direction IDs: `clinical`, `simulation`, `measurement`, `methods`, `education`. Each count and evidence ID list reflects deduplicated eligible records first published within the previous seven days, not revisions. Papers belong to one strongest keyword-matched direction. The fixed questions are editorial prompts, not generated conclusions. Counts are public query samples, not exhaustive rankings or measured growth; zero is not evidence of no activity.

## Failure behavior

`lastAttemptAt` and per-source results always record an attempted fetch. If any source fails, existing successful daily and weekly content and their timestamps are preserved. On first initialization only, a partial source sample can populate three daily entries and the five weekly directions, with an explicit warning. If fewer than three daily candidates exist, the old daily list and success timestamp remain unchanged; an empty first run stays empty. A successful fetch with zero weekly matches can legitimately produce five zero counts, labeled as sampled coverage. Warnings/errors exit nonzero after writing output, so failures remain visible in both dashboard and Actions. A malformed curated input or invalid prior JSON fails before writes; workflow logs expose that input-validation error rather than destroying content.

The tests are offline fixtures for relevance, deduplication, diversity, date bounds, weekly sample counts, partial/all provider failures and successful timestamp preservation. They do not establish live API availability. The refresh may be run manually in a network-enabled environment to verify current provider responses; an outbound-access restriction is not a reason to bypass that restriction.
