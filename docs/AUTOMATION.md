# Public metadata automation

Run `python -m unittest discover -s tests -p 'test_*.py' -v`, then `python scripts/refresh.py` with Python 3.10+. No third-party Python dependencies or API credentials are needed. The script reads and validates the separately curated `data/research.json` and `data/graph.json`, but never edits them. Only `data/radar.json` and `site/radar-data.js` are generated. Use `--root PATH` for another checkout and `--force-weekly` to manually rebuild the weekly sample.

The GitHub Actions workflow runs daily at 06:00 UTC on main (actual execution may be delayed by GitHub). Weekly summaries update on Monday UTC, or on first successful initialization. If Monday fails, the next successful run catches up once for the current UTC week. Manual workflow runs refresh the daily list and catch up an overdue weekly sample. Changes to scripts, tests, application source, curated research or the workflow trigger verification runs. JavaScript view regressions and deterministic graph/bibliography regeneration are also checked. Actions must be enabled and the repository must permit the built-in token to push to main; protected-branch requirements can block commits. There is no Pages deployment, external publishing, private-data access, or extra secret. The only requested token permission is `contents: write`. The workflow runs tests, records refresh status, commits both generated files even when metadata providers fail, uploads the standalone site as a downloadable artifact, then marks the run unsuccessful for insufficient/all-failed updates. A usable partial update can complete successfully but retains explicit partial-source status in the data and UI; workflow success does not imply that every source succeeded. GitHub may disable scheduled workflows in inactive public repositories.

## Sources, dates and selection

Europe PMC's public REST search returns up to 300 core metadata records across three cursor pages, constrained to first publication within 90 days. arXiv's public Atom API returns up to 200 newest submitted matches. Both broad queries require LLM terms plus psychology-related topics. Abstract text is used only in memory for matching; output contains title, URL, dates and descriptive metadata, not full texts. Ordinary failed requests receive two bounded retries, then a visible source error. HTTP 429 stops immediate retries and sets a persisted 24-hour cooldown.

Local screening requires an LLM term in the title or at least two LLM mentions in the abstract, plus one of the five psychology topic vocabularies. Education additionally requires a psychological process or learning-outcome signal such as metacognition, motivation, self-regulation or learning transfer. Cognitive/social research is not automatically described as human simulation. Matched signals are saved. Methods matches additionally require psychological/human research context. This is a transparent heuristic, not full-text screening. It can miss papers, misclassify ambiguous matches, and reflects source coverage and query caps. Europe PMC records are labeled `paper` (not a peer-review guarantee) unless explicitly preprints; arXiv entries are `preprint` even if a later journal version exists. This implementation retrieves papers/preprints, not social-media posts. No attempt is made to infer clinical efficacy or research quality.

After merging the retrieved versions, the earliest valid date observed in that group becomes `publishedAt`; the representative linked version keeps `recordPublishedAt`, and `versions` records the observed alternatives. Only group dates within the previous 90 days qualify. This is the earliest **retrieved** date, not a guarantee of a work's first public appearance; the source queries may omit earlier preprints. Future/missing publication dates are excluded; missing, inconsistent or future `updatedAt` becomes null. Europe PMC does not supply a trusted revision date here, so `updatedAt` remains null. A newly revised older arXiv paper is not treated as newly published. Duplicate groups use DOI, normalized title or source ID, including transitive matches, before date filtering. A paper record remains the preferred title/link representative, while the group's earliest known date is preserved. DOI-less differently titled versions may remain undetected.

Daily selection score: `90 - age_in_days + 3 * min(title_topic_hits, 3)`, descending, with source ID as deterministic tie breaker. Select one per direction first, then fill to three only when fewer directions are available. Thus multiple clinical papers do not crowd out eligible alternatives. The score measures metadata relevance and freshness, never scientific quality.

Weekly output has exactly five preset bilingual direction IDs: `clinical`, `simulation`, `measurement`, `methods`, `education`. Counts use each group's earliest retrieved date in the previous seven days. Items are ordered by count, and each stores an auditable `papers` list with title, URL, date and matching signals, as well as source IDs. `weeklySample` records the window, source counts, query definitions, eligible count and whether provider caps were reached. Papers belong to one strongest keyword-matched direction, weighting title signals more heavily than abstract signals. The fixed questions are editorial prompts, not generated conclusions. Counts rank the five preset categories within this public query sample; they are not the field's global top five or measured growth. Zero is not evidence of no activity. A screening-policy version change forces the weekly snapshot to rebuild when a source succeeds.

## Failure behavior

`lastAttemptAt` and per-source results always record an attempted refresh. If at least one source is healthy and supplies three eligible candidates, daily content refreshes with `dailyCoverage: partial` when another source is unavailable. `lastCompleteDailyAt` is updated only when every source succeeds. Weekly updates similarly carry `weeklyCoverage` and `lastCompleteWeeklyAt`; they retain their weekly cadence. The UI explicitly warns that source coverage is incomplete, and sampled weekly counts carry that warning too.

If all sources fail, successful content and its update timestamps remain unchanged. If fewer than three daily candidates exist, the old daily list and timestamp remain unchanged; an empty first run stays empty. A successful source with zero weekly matches can legitimately produce five zero counts, labeled as sampled coverage. A rate-limited source is marked `deferred` until its persisted cooldown expires, without making another request. Partial coverage is a usable degraded result, not a full success. Insufficient/all-failed updates exit nonzero after writing status. Malformed curated input or invalid prior JSON fails before writes rather than destroying content.

The tests are offline fixtures for relevance, deduplication, diversity, date bounds, weekly sample counts, partial/all provider failures and successful timestamp preservation. They do not establish live API availability. The refresh may be run manually in a network-enabled environment to verify current provider responses; an outbound-access restriction is not a reason to bypass that restriction.
